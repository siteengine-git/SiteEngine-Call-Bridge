# 0.1.4 callback repair candidate — unaccepted, not installed

Installed 0.1.3 synthetic callback acceptance produced **25 PASS / 5 FAIL**.
All expected signatures were calculated independently with Python standard-library
HMAC-SHA1 over the exact HTTPS URL and sorted form fields, not the plugin validator.
Responses were checked against actual owned persisted rows. No calls were made,
recording remained off and an inert `.invalid` marker was never fetched.
Operational identities, request/state receipts and cleanup evidence stay private.

Four defects account for the five native failures:

- A valid query/body collision signature was rejected; a signature omitting the
  colliding body field was incorrectly accepted and persisted an owned test call.
- WordPress magic-quoted POST values caused a legitimate apostrophe-bearing
  request to fail signature validation.
- A late progress status replaced a completed/qualified outcome.
- An `absent` recording notification erased a completed inert recording marker.

[Twilio's signature rules](https://www.twilio.com/docs/usage/webhooks/webhooks-security)
keep query parameters in the exact URL and append all separate form parameters.
The [provider SDK](https://github.com/twilio/twilio-python/blob/main/twilio/request_validator.py)
independently confirms that division. Repeated query keys remain part of the raw
URL; they do not justify removing a same-named body field.
[Call callback documentation](https://www.twilio.com/docs/voice/api/call-resource)
also warns that event HTTP requests can arrive out of order.

The repair touches five runtime files: SignatureValidator, Voice/Status/Recording
controllers and CallLogRepository. It signs the unslashed form body in full,
consumes the same authenticated values, keeps progress monotonic and retains the
first terminal call outcome. Only complete recording markers are attached; later
notifications preserve an existing completed marker. Conditional SQL updates
compare the callback fields read earlier, so an intervening winner is preserved.
There is no retry over a conflicting winner, schema change or event journal.

This conservative first-final/first-completed policy does not reconcile differing
terminal outcomes or later legitimate recording corrections. Review that bounded
policy before installed acceptance. Native conditional SQL behavior has not been
tested for this repair; local controlled interleavings are doubles only.

Focused child-process tests execute actual controllers/validator with fake
WordPress/DB adapters (controllers emit and exit). The preserved initial suite
was 8 PASS / 14 FAIL; the expanded repaired suite is **28 PASS / 0 FAIL** on the
existing local PHP 8.5.12 executable. Added checks cover exact encoded GET URLs,
collisions, magic quotes, terminal/progress ordering, duration thresholds, unknown
calls/statuses, legacy recording bodies and conditional-write interleavings.
Local lint: eight changed/new PHP files PASS. Native SQL, installed repaired HTTP,
allocator/DNI/Base suites and live telephony are not claimed or repeated.

Known/unknown routing, recording-off TwiML, escaped new/repeat whispers, duplicate
voice identity, parent Dial-action qualification, short/busy/no-answer outcomes,
unknown callbacks and duplicate markers passed in the installed 0.1.3 run.
Dial actions correlate through the parent CallSid; child-only callbacks were
acknowledged unmatched without altering it. The current schema/code does not
persist DialCallSid as a child-leg mapping. Do not call that durable child-link
acceptance or introduce a new call-identity model here.
